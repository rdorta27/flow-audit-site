Architecture

Flow Audit is a local-first command line tool: evidence goes in, a report comes out. Today the engine reads export files, joins the records and runs the five rules; showing its own report on this site is what is missing.

Pipeline

Components

Hexagonal layout (ADR 0002). The domain imports nothing outside src/domain/, and a test fails the build if that changes. An arrow means “depends on”.

domain/
The canonical model and the pure logic: events, orders, journeys, findings and impact, the join of records with its confidence, the classification of time (work, wait, gap) and the five rules. No I/O, no clock, no files.
ports/
The four interfaces the rest of the engine depends on: EvidenceSource, CatalogSource, ReportRenderer and Clock.
adapters/
The outside world. A clock, the export serializers and the readers.
app/
The runAudit() use case. It ties ingestion, reconstruction, detection, quantification and rendering together, and owns no format.
cli/
Argument parsing, help and exit codes. Seven commands: audit, read, explain, stub, dataset, diff and engagement.
dataset/
A deterministic generator with a fixed seed. It writes the synthetic Ortelis evidence: 5,000 orders in September 2026 and the minutes per task.

What runs today

  • deno task check type-checks the CLI, the generator, the clock adapter and the tests. It passes.
  • deno task test passes: dataset, serializers, the architecture and license boundaries, the skeleton, the test server, the three readers, the join and the rules.
  • deno task audit runs the audit: it reads the files, joins the records, applies the five rules and writes findings.json and report.html. read (counts and joins records) and explain (one duplicated order, step by step) also run.
  • deno task dataset regenerates the 5,000 orders from a fixed seed. Two runs produce byte-identical exports.

Design

  • Ingestion. Reads the exports of the product catalog, order manager, process orchestrator and activation system.
  • Reconstruction. Joins the records of one order through the identifiers each system already carries (explicit link) and, only when they are missing, infers through another field, such as the terminal serial. Every link says how sure it is. The time window is not used yet.
  • Rules. Five rules detect failures without retry, manual waits, expired timers, duplicates and a missing identifier.
  • Impact. Multiplies the affected orders by the minutes of work for each case. Hours are an estimate; affected orders come first.
  • Severity. Derives the severity from the hours per month. Nobody assigns it by hand.
  • Report. Generates one self-contained HTML file and a findings.json with the evidence of each finding.
