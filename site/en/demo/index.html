Example: audit of
Ortelis Satellite

Example with synthetic data from an invented operator. The engine already detects the five problems from files; this page is still written by hand in the shape of the real report, which you can open as the engine's report. Hours are an estimate with example minutes (config.json), not measured at any operator.

Executive summary

A synthetic order, ORD-1005, takes 69 hours. It should take less than one. Nobody works 60 of those hours: they are a gap between systems that no process owns.

Priority: add capacity_profile to the technical catalog (4,167 orders). Retry the activation before the manual queue (400 orders). Compensate the 48-hour timer (50 orders). The three actions cover 97% of the estimated hours, with example assumptions not measured at any operator.

Assumptions

The hours are an estimate built on four example rates. None is measured at any operator; they can be changed in config.json. The orders affected do not depend on them.

RateMinutes per caseFinding that uses it
Manual handling manual_minutes5R01, R02, R03
Daily follow-up daily_followup_minutes15R01, R03
Clean-up cleanup_minutes90R04
Investigation investigation_minutes45R05

Where the days go

An order from the synthetic dataset, ORD-1005: 69 hours end to end. Nobody works 60 of them.

work by a system manual wait gap with no event

The gap starts when the first attempt fails. It ends when someone retries by hand 60 hours later. In that interval there is no event: no declared wait and no scheduled retry.

Findings

The example shows five findings over the same month of orders.

R01 Activation failure with no retry

Cohort
400 orders · 8%
Estimate (example assumptions)
283.3 h/month
hours = affected × (rates.manual_minutes + wait_days × rates.daily_followup_minutes) / 60; wait_days = 2.5

Action

Retry automatically with backoff before the manual queue.

R02 Manual capacity check for a missing attribute

Cohort
4,167 orders · 83.3%
Estimate (example assumptions)
347.3 h/month

Synthetic case: 83% of the demo orders; those sold on the offer's second version do not have the problem.

hours = affected × rates.manual_minutes / 60

Action

Add capacity_profile to the spec. Automate the beam assignment.

R03 The process orchestrator timer expires without compensation

Cohort
50 stuck orders (of 150 with an expired timer) · 1%
Estimate (example assumptions)
317 h accumulated to period end

The engine evaluates it on files; on the simulated server it is not evaluated.

hours = stuck × (rates.manual_minutes + days_stuck × rates.daily_followup_minutes) / 60; stuck = 50, days_stuck ≈ 25

Action

Close or requeue the order at 48 h. 50 orders ended up stuck.

R04 The order manager retry duplicates the service order

Cohort
20 orders · 0.4%
Estimate (example assumptions)
30 h, one-off (clean-up of the audited month)
hours = duplicates × rates.cleanup_minutes / 60

Action

Retry idempotently, using the order key.

R05 No end-to-end correlation identifier

Cohort
300 orders · 6%
Estimate (example assumptions)
225 h/month
hours = incidents_per_month × rates.investigation_minutes / 60

Action

Use one common id in the four systems, from the order to the attempt.

Estimate with example assumptions (R01 to R04)
978 h per month of manual work and waiting, with minutes per case that are not measured at any operator. R05 (225 h) is counted apart, as a traceability risk, until real measurements exist.
