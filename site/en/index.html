Where do orders get stuck?
Flow Audit will find out.

What you can do here: follow an order from start to finish, see where it broke and what it cost, and open a sample report.

Flow Audit is a tool that checks how an order moves from the moment a customer buys to the moment the service works. It will show where each order stops and what each failure costs.

It is for telecom operators and for the people who audit their sales and activation systems.

1 · The journey

A customer orders satellite internet

Order ORD-1005, from the made-up operator Ortelis. It should work in one hour. It worked at hour 69.

What you can do: press Next or Play to watch the order jump from system to system. Under each system appears what it notes, and below, apart, Flow Audit reads those notes. At every step compare what is known without Flow Audit and with Flow Audit.

  • Sales channel
  • Product catalog CAT
  • Order manager OMS
  • Process orchestrator BPM
  • Activation system PROV
  • Flow Audit (outside the path)
  1. 0 h · Sales channel. Ana orders “SkyHome 200”, satellite internet, on the operator's website.
  2. +1 min · Product catalog. The catalog confirms the offer exists. But its technical sheet lacks one piece of data: the satellite's capacity profile.
  3. +3 min · Process orchestrator. Because the data is missing, the orchestrator opens a task for a person. An analyst checks the capacity by hand: 2 hours. Problem: A field is missing in the catalog and someone fills it in by hand R02.
  4. +2 h · Order manager. The order manager splits the order into technical work: a service order to activate the line and a work order to install the dish. The service order is born here.
  5. +3 h · Process orchestrator. A technician installs the dish at Ana's home. The installation ends well.
  6. +9 h · Activation system. The activation system tries to switch the service on. The satellite equipment does not answer and the attempt fails. Nobody schedules another attempt. Problem: Activation fails and nobody retries it R01.
  7. +69 h · Order manager. 60 hours later, Ana calls. Someone retries by hand, but the order manager creates a new service order for the same line instead of repeating the first one. A second service order is born. Problem: A retry creates a second service order R04.
  8. +69 h · Activation system. The second attempt works. Ana has internet 69 hours after ordering it.
The difference

The same order, told two ways

Without Flow Audit

  • Five teams, five screens. Each sees that its part went well.
  • The 60 hours of inactivity appear in no system.
  • The audit is done with interviews and spreadsheets. The cost is an opinion.
  • Two audits of the same operator reach different conclusions.

With Flow Audit

  • One journey per order, built from what each system already notes.
  • Each problem points to the order and the records that prove it.
  • Each cost shows its calculation, with the client's own rates.
  • With the same data, the result is always the same. It touches no system.

The five problems it looks for

Each problem has a code, R01 to R05. Figures are monthly, for an operator with 5,000 orders, using made-up data.

The five problems in the example and their estimated monthly cost.
CodeWhat happensCost per month
R01The activation fails and nobody retries it. The order waits about 2.5 days.≈ USD 12,750
R02A catalog field is missing and someone fills it in by hand on 8 orders out of 10.≈ USD 15,626
R03A timer expires and the process does nothing: the order is left inactive.≈ USD 14,267, plus USD 3,250 of revenue at risk
R04A retry creates a second service order for the same order.≈ USD 1,590
R05The systems share no order number. Investigating an incident takes about 45 minutes.≈ USD 10,125
In total: about USD 54,358 a month in operating cost, plus USD 3,250 of revenue at risk. These are illustrative figures worked out from made-up data.

What problem does it solve?

An order passes through five systems. Each system sees only its own part.

Nobody sees the whole path

The sales system says the order is fine. The activation system says it never arrived. Nobody knows where it got lost.

Failures cost money

A duplicate order gets billed twice. An activation without an order wastes resources. A waiting order delays billing.

Flow Audit joins the pieces

It will read the five systems, join the data for each order and show where the path breaks.

What will you get?

A report in one file

A page that opens in any browser, offline. It has a summary, the order path and the problems found.

Proof for each problem

Each problem names the order, the data that proves it and how its cost was calculated.

Repeatable results

With the same data, the audit always gives the same result.

What is being built?

Two stages. The second does not start until the first works.

Stage 1 · First real report

Read orders, service orders and activations from the test server, detect problem R04 (duplicate orders) and produce a report with its cost and formula. The cost of R04 is USD 1,590: USD 1,350 of manual clean-up plus USD 240 of duplicate activations, already measured because activations are linked to their service order.

Stage 2 · Ready for a client

Read the files a real client exports (CSV or JSON), using a configuration that translates their columns, and also detect R01, R02 and R05. This is what makes a first real audit possible.

Later

R03 and the orchestration system, a PDF report, a web interface and the engine languages.

Done · version 0.3.3

A made-up operator with 5,000 test orders. A server that delivers them the way a real system would. An example report. Three readers (orders, service orders and activations): they already read all 5,000 orders, 5,020 service orders and 5,400 activation attempts, every record carries its origin and they are joined, saying how sure each link is; rule R04 already finds the 20 duplicate orders and values them at USD 1,590.

Questions

Can I use it now?

No. It is under construction. The analysis will come in the next versions.

Where will it run?

On the auditor's computer, from the command line. It will not need a server or a database.

Will customer data leave?

No. Data goes in, a folder with the report comes out. Nothing is sent to outside services.

Will it change the systems?

No. It only reads. It never creates, changes or deletes orders.

Is it for sale?

Not yet. It is a test project. The idea is to offer fixed-price audits on a client's data and, later, to license the tool to consultancies.

Glossary

The words this page uses, in order of appearance.

Order
What a customer buys, for example “SkyHome 200”. The sales channel receives it.
Order line
Each product inside an order. An order can have several lines.
Service order
The technical instruction the order manager creates to activate a line. There should be one per line.
Work order
The task for a person or crew, for example installing the dish.
Activation attempt
Each time the activation system tries to switch the service on. It can work or fail.
Retry
Trying again an activation that failed. It should reuse the original service order, not create another.
Link (explicit, inferred, missing)
How a record is joined to its order. Explicit: it carries the number. Inferred: deduced from other data, with less certainty. Missing: it could not be joined and stays in view.
Evidence
The specific records that prove a problem.
Snapshot vs history
A snapshot is the current state of a record; history is everything that changed and when. Measuring waits needs the history.
Gap
Time in which an order has no event at all: nobody does anything.
Finding
A problem the audit found, with its evidence and its cost.
Loaded hour
One hour of work at its rate (for example USD 45), used to price manual work.
Revenue at risk
Money not yet collected or that could be lost because the service is not activated.
BSS and OSS
An operator's systems. BSS handles sales and billing. OSS handles the network and activation.
TM Forum (TMF)
An industry association that publishes common formats so these systems can exchange data.
Test server
Our own program that imitates a real system with made-up data. It always states that the data is simulated.
