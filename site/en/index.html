Architecture

Core concept

Flow-Audit is an audit tool. It reads the records of four systems and rebuilds the path of each order. For each loss it calculates the hours, the dollars and the evidence.

Physical analogy

Picture a parcel that crosses four warehouses. Each warehouse writes down only its own arrivals and departures.

Nobody knows where the parcel sat for three days. Flow-Audit puts the four notebooks together. It marks the warehouse where the parcel waited and adds up the cost of that wait.

Technical mechanics

  • Ingestion. Reads the exports of the catalog, OMS, BPM and provisioning.
  • Reconstruction. Joins the events of one order with a time window, because the systems share no identifier.
  • Rules. Five rules detect failures without retry, manual waits, expired timers, duplicates and a missing identifier.
  • Impact. Multiplies the affected orders by the minutes of work and by the loaded hourly cost.
  • Severity. Derives the severity from the hours per month. Nobody assigns it by hand.
  • Report. Generates one self-contained HTML file and a findings.json with the evidence of each finding.

What it audits

Four systems, one order. Other systems appear as context and stay out of scope.

01 · Catalog

The offer and its spec

Checks that the offer can be sold. Checks that the technical spec has the attributes provisioning needs.

02 · OMS

The decomposition

Follows how the commercial order splits into service orders (SO) and work orders (WO). Counts dependencies, retries and fallout, the orders that leave the automatic flow.

03 · BPM

The orchestration

Detects where the process waits, which timer expires without compensation and which task ends by hand.

04 · Provisioning

The activation

Counts the activation attempts, records which ones fail and measures how long the confirmation takes.

What it delivers

A self-contained report

One HTML file with no external assets. It holds the summary, flow map, state machine, timeline and findings.

Findings with evidence

Each finding stores in findings.json the order, the events that triggered it and the impact formula.

A reproducible dataset

The normalized evidence and the configuration stay versioned. Repeating the audit means running it again.

A reading for the client

Shows the full map, the monthly cost and the three priority fixes.

Where it stands

The demo puts visuals first. The report is designed first. The engine that fills it comes after.
