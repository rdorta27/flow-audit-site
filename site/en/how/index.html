How an audit is run

Five steps, from the systems’ files to a report. Commands are typed in the core/ folder of the repository; the outputs are the demo’s (data/demo), trimmed.

1. Export one file per system

What you give

One export from each system: catalog, order manager, process orchestrator and activation system, for the same month. Which fields, format and period each one needs: the export table.

What you type

Nothing. Each system exports with its own tool.

What comes out

Four files in one folder:

catalog.json
oms_orders.csv
bpm_history.jsonl
provisioning.jsonl

2. Write the mapping

What you give

What the columns of your exports are called, what each state means, the date format and the time zone.

What you type

You edit mapping.json; the demo’s is a starting point.

What comes out

A mapping.json. A piece of the demo’s:

  "oms": {
    "file": "oms_orders.csv",
    "format": "csv",
    "date_format": "iso8601",
    "time_zone": "UTC",
    "columns": {
      "order_ref": "order_ref",
      "submitted_at": "submitted_at",
      ...
    },
    "states": { ... }
  },

3. Pass the quality gate

What you give

The folder with the exports and the mapping.

What you type
deno task audit --dataset <dir> --mapping <file> --check
What comes out

It reads, joins by order and measures the quality of the data. No rule runs and no report is written. If the gate fails, it exits with code 3.

4. Run the audit

What you give

The same folder and the same mapping. The output folder must exist.

What you type
deno task audit --dataset <dir> --out out
What comes out

The five rules, with orders affected and hours estimated with example minutes, and the report files:

R01@1 · 400 orders · estimate 283.3 h
R02@1 · 4,167 orders · estimate 347.3 h
R03@1 · 50 orders · estimate 317 h
R04@2 · 20 orders · estimate 30 h
R05@1 · 300 orders · estimate 225 h
4,467 of 5,000 orders have a problem (estimate 925.9 h with the example rates, each order once)
flow-audit: wrote out/findings.json
flow-audit: wrote out/report.html
flow-audit: wrote out/findings.csv
flow-audit: wrote out/quality.json

5. Read the report

What you give

The out/ folder from the previous step.

What you type

Open out/report.html in a browser. It works offline.

What comes out

One page with the summary, the journey and each problem with its proof and cause, plus findings.json, findings.csv and quality.json. This is what the demo’s looks like: the engine’s report.

When…

  • the client’s data must not sit in the repository: --engagement <dir> or the FLOW_AUDIT_HOME variable point to a folder outside it, with raw/, mapping/, config/ and out/.
  • the quality gate fails and you still want to see the rules: --force. The answer says it was forced.
  • the report leaves your machine: --redact --client <name> replaces order and serial numbers with pseudonyms and marks the report as confidential.
  • you want to compare two audits: deno task diff a b, with two findings.json files.
