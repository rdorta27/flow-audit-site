Auditoría de pedidos de telecomunicaciones En construcción · versión 0.2.0

¿Dónde se atascan los pedidos?
Flow Audit lo encontrará.

Flow Audit es una herramienta para revisar cómo avanza un pedido desde que el cliente compra hasta que el servicio funciona. Señalará dónde se detiene cada pedido y cuánto cuesta cada falla.

Es para operadores de telecomunicaciones y para quienes auditan sus sistemas de venta y activación.

Ver el informe de ejemplo Ver cómo funcionará
Todavía no analiza datos. Hoy existen datos de prueba, un servidor de prueba y un informe de ejemplo.

¿Qué problema resuelve?

Un pedido pasa por cuatro sistemas. Cada sistema ve solo su parte.

Nadie ve el recorrido completo

El sistema de ventas dice que el pedido está bien. El de activación dice que no le llegó nada. Nadie sabe dónde se perdió.

Las fallas cuestan dinero

Un pedido duplicado se cobra dos veces. Una activación sin pedido gasta recursos. Un pedido que espera retrasa el cobro.

Flow Audit une las piezas

Leerá los cuatro sistemas, unirá los datos de cada pedido y mostrará dónde se rompe el recorrido.

¿Qué revisará?

Estos son los cuatro sistemas que recorre un pedido, en orden.

1 · Catálogo

Lo que se vende

Comprobará que cada oferta tenga los datos técnicos necesarios para activarla.

2 · Gestión de pedidos

Cómo se reparte el pedido

Seguirá cómo un pedido se divide en tareas técnicas. Contará los reintentos y los pedidos que necesitan intervención manual.

3 · Orquestación

Quién hace cada paso

Detectará dónde espera el proceso y qué tareas terminan a mano.

4 · Activación

Cuándo funciona el servicio

Contará los intentos de activación, cuáles fallan y cuánto tarda la confirmación.

¿Qué obtendrá?

Un informe en un solo archivo

Una página que se abre en cualquier navegador, sin conexión. Incluye un resumen, el recorrido y los problemas encontrados.

Pruebas de cada problema

Cada problema indica el pedido, los datos que lo demuestran y cómo se calculó su costo.

Resultados repetibles

Con los mismos datos, la auditoría da siempre el mismo resultado.

Hecho · versión 0.2.0

Un operador inventado con 5.000 pedidos de prueba. Un servidor que entrega esos pedidos como lo haría un sistema real. Un informe de ejemplo.

Ahora

Un lector que toma los pedidos del servidor de prueba sin modificarlos.

Después

Unir los datos de cada pedido, detectar pedidos duplicados y generar el informe real.

Lo que todavía no hace. No lee datos de clientes. No detecta problemas. No genera informes. Las cifras del ejemplo salen de datos inventados.

Preguntas frecuentes

¿Ya se puede usar?

No. Está en construcción. El análisis llegará en las próximas versiones.

¿Dónde se ejecutará?

En el equipo de quien audita, desde la línea de comandos. No necesitará servidor ni base de datos.

¿Saldrán datos del cliente?

No. Los datos entran, sale una carpeta con el informe. Nada se envía a servicios externos.

¿Modificará los sistemas?

No. Solo leerá. Nunca creará, cambiará ni borrará pedidos.

Glosario

BSS y OSS

Los sistemas de un operador. BSS gestiona ventas y cobros. OSS gestiona la red y la activación.

TM Forum (TMF)

Asociación del sector que publica formatos comunes para que estos sistemas intercambien datos.

Servidor de prueba

Un programa nuestro que imita un sistema real con datos inventados. Siempre avisa de que los datos son simulados.
