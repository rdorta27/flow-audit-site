Orders cost about 925.9 h of manual rework a month

Flow Audit read 5,000 orders from Product catalog, Order manager, Process orchestrator, Activation system (6 sources) and looked for 5 patterns that make people redo work by hand. Measured: 5,000 orders, 4,937 with a finding. Projected: 925.9 h a month, from minutes you can change; not money, not a booked loss.

Where the hours go

  1. Missing catalog attribute forces a manual task (R02) 347.3 h in 4,167 orders
  2. Timer expires and nobody compensates (R03) 317 h in 50 orders
  3. Activation fails and nobody retries (R01) 283.3 h in 400 orders

What it could not see. Product catalog: which version of an offer applied to an order: the catalog holds validity dates only. Order manager: when each state change happened: a row holds the current state and its creation time.

How to read this report

The top says where the hours go. Each finding below is written in the same order: what happens, in how many orders, how many hours, how they were counted, the proof and what to do. Counts of orders are measured in the records; hours are projected from minutes you can change, so they are an estimate. The drawing of one order shows its path through the systems and marks in red what could not be seen and where the problem starts. Words with a dotted underline are explained in the glossary, and long lists are folded away.

Glossary

Activation fails and nobody retries (R01)
An activation failed and nothing tried it again within the retry window, so a person has to find the order and push it through by hand.
Missing catalog attribute forces a manual task (R02)
The product's technical spec lacks a value the activation system needs, so a person fills it in by hand on every order.
Timer expires and nobody compensates (R03)
A process timer expired, nothing followed it and the order has been without service for days, until a person finds it.
Duplicate service order (R04)
A second service order exists for the same order line. When activation failed, a retry created a new order instead of reusing the first.
No end-to-end correlation id (R05)
Some records cannot be tied to their order by an id they carry, so a person has to work out which belong together.
Product catalog (CAT)
Holds what can be sold and how it is activated.
Order manager (OMS)
Receives the customer's order and splits it into service orders.
Process orchestrator (BPM)
Runs the steps of each order, one after another.
Activation system (PROV)
Turns the service on in the network. Each try is an activation attempt.
