4,467 of 5,000 orders have a problem that a person has to fix by hand

Flow Audit read 5,000 orders from Product catalog, Order manager, Process orchestrator, Activation system (6 sources) and looked for 5 patterns that make people redo work by hand. Measured: the orders and records counted in the data. Hours are an estimate that only helps rank what to fix first; they rest on the assumptions below. Flow Audit finds and measures; fixing the cause is the operator's work.

  • What was audited. 5,000 internet orders (a customer's request to get an internet service installed and switched on), read from Product catalog, Order manager, Process orchestrator, Activation system. Period: 2026-09-01 to 2026-09-30.
  • What went wrong. 4,467 of them needed a person to fix something by hand. The most common problem is Missing catalog attribute forces a manual task (R02), in 4,167 orders.
  • Where to start. Missing catalog attribute forces a manual task: Add the missing attribute to the spec of the offer version, so the activation system gets it without a manual step. The hours are freeable capacity, not savings.

Most orders affected

  1. Missing catalog attribute forces a manual task (R02) Measured 4,167 orders: The product's technical spec lacks a value the activation system needs, so a person fills it in by hand on every order.
  2. Activation fails and nobody retries (R01) Measured 400 orders: An activation failed and nothing tried it again within the retry window, so a person has to find the order and push it through by hand.
  3. No end-to-end correlation id (R05) Measured 300 orders: Some records cannot be tied to their order by an id they carry, so a person has to work out which belong together.

Glossary

Activation fails and nobody retries (R01)
An activation failed and nothing tried it again within the retry window, so a person has to find the order and push it through by hand.
Missing catalog attribute forces a manual task (R02)
The product's technical spec lacks a value the activation system needs, so a person fills it in by hand on every order.
Timer expires and nobody compensates (R03)
A process timer expired, nothing followed it and the order has been without service for days, until a person finds it.
Duplicate service order (R04)
A second service order exists for the same order line. When activation failed, a retry created a new order instead of reusing the first.
No end-to-end correlation id (R05)
Some records cannot be tied to their order by an id they carry, so a person has to work out which belong together.
Product catalog (CAT)
Holds what can be sold and how it is activated.
Order manager (OMS)
Receives the customer's order and splits it into service orders.
Process orchestrator (BPM)
Runs the steps of each order, one after another.
Activation system (PROV)
Turns the service on in the network. Each try is an activation attempt.
Product orders (TMF622)
The standard way to read customer orders.
Service orders (TMF641)
The standard way to read service orders, the technical work behind an order.
Activations (TMF640)
The standard way to read activation attempts.

What a customer bought, as the order manager recorded it.

The technical work created from one order line. One line should have one.

The moment the service is switched on. A failed attempt is tried again.

One pattern the audit looked for and, when it found it, how many orders it touches.

One occurrence of the pattern that somebody has to deal with by hand.

Counted in the records. Orders, cases and records are measured.

A what-if worked out from the same orders and rates. It is not a promise.

Assumption
A number chosen or declared, such as minutes per case. It was not measured.

The orders and records the finding rests on, so anyone can look them up.
