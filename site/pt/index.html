Auditoria de pedidos de telecomunicações Em construção · versão 0.2.0

Onde os pedidos travam?
O Flow Audit vai descobrir.

O Flow Audit é uma ferramenta para verificar como um pedido avança desde a compra do cliente até o serviço funcionar. Vai mostrar onde cada pedido para e quanto custa cada falha.

É para operadoras de telecomunicações e para quem audita seus sistemas de venda e ativação.

Ver o relatório de exemplo Ver como vai funcionar
Ainda não analisa dados. Hoje existem dados de teste, um servidor de teste e um relatório de exemplo.

Que problema resolve?

Um pedido passa por quatro sistemas. Cada sistema vê só a sua parte.

Ninguém vê o caminho completo

O sistema de vendas diz que o pedido está certo. O de ativação diz que nada chegou. Ninguém sabe onde ele se perdeu.

As falhas custam dinheiro

Um pedido duplicado é cobrado duas vezes. Uma ativação sem pedido gasta recursos. Um pedido parado atrasa a cobrança.

O Flow Audit junta as peças

Vai ler os quatro sistemas, juntar os dados de cada pedido e mostrar onde o caminho se rompe.

O que vai verificar?

Estes são os quatro sistemas por onde passa um pedido, em ordem.

1 · Catálogo

O que se vende

Vai verificar se cada oferta tem os dados técnicos necessários para ativá-la.

2 · Gestão de pedidos

Como o pedido se divide

Vai seguir como um pedido se divide em tarefas técnicas. Vai contar as novas tentativas e os pedidos que precisam de trabalho manual.

3 · Orquestração

Quem faz cada passo

Vai encontrar onde o processo espera e quais tarefas terminam à mão.

4 · Ativação

Quando o serviço funciona

Vai contar as tentativas de ativação, quais falham e quanto demora a confirmação.

O que você vai receber?

Um relatório em um só arquivo

Uma página que abre em qualquer navegador, sem internet. Traz um resumo, o caminho do pedido e os problemas encontrados.

Provas de cada problema

Cada problema indica o pedido, os dados que o comprovam e como o custo foi calculado.

Resultados repetíveis

Com os mesmos dados, a auditoria sempre dá o mesmo resultado.

Feito · versão 0.2.0

Uma operadora inventada com 5.000 pedidos de teste. Um servidor que entrega esses pedidos como um sistema real faria. Um relatório de exemplo.

Agora

Um leitor que pega os pedidos do servidor de teste sem alterá-los.

Depois

Juntar os dados de cada pedido, encontrar pedidos duplicados e gerar o relatório real.

O que ainda não faz. Não lê dados de clientes. Não encontra problemas. Não gera relatórios. Os números do exemplo vêm de dados inventados.

Perguntas frequentes

Já posso usar?

Não. Está em construção. A análise chega nas próximas versões.

Onde vai rodar?

No computador de quem audita, pela linha de comando. Não vai precisar de servidor nem de banco de dados.

Os dados do cliente vão sair?

Não. Os dados entram, sai uma pasta com o relatório. Nada é enviado a serviços externos.

Vai alterar os sistemas?

Não. Só lê. Nunca cria, altera nem apaga pedidos.

Glossário

BSS e OSS

Os sistemas de uma operadora. O BSS cuida de vendas e cobrança. O OSS cuida da rede e da ativação.

TM Forum (TMF)

Associação do setor que publica formatos comuns para esses sistemas trocarem dados.

Servidor de teste

Um programa nosso que imita um sistema real com dados inventados. Sempre avisa que os dados são simulados.
